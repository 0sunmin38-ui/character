# viewer: 작업 뷰어

**에셋 화면.** 사전 → 태그조합 → 최종 → 생성기.

캐릭터(챗봇 프롬프트) 화면은 여기 없다. **`character` 브랜치**에 있다.
Claude 와 같이 써야 하는 작업이라 혼자 돌리는 이 화면과 성격이 달라 갈라 뒀다.

## 파일 구성

빌드는 없다. 정적 파일 몇 개뿐이다.

```
viewer/
  index.html            셸 (37줄)
  css/app.css           스타일
  js/core.js            뼈대: 저장소 읽기 · 마크다운 · 저장/초안 · 생성기 · 탭 · 패널
  js/asset.js           에셋 화면
  js/_docs.parked.js    문서 열람 화면 (지금은 안 부름)
  css/_docs.parked.css  위의 스타일 (지금은 안 부름)
```

`core.js` 는 화면을 모른다. 화면 쪽이 `PAGE` 하나를 정의해 두고 core 를 먼저 불러 붙인다.

```js
const PAGE = {
  side : 'img' | 'bot',        저장·생성기가 어느 쪽 것을 보는가
  tabs : [[키, 이름], …],
  views: { 키: 그리는 함수 },
  load : async (get) => {},    (선택) 이 화면만 읽는 자료
  afterSave: () => {},         (선택) 저장 뒤 할 일
};
```

core 는 화면 함수를 직접 부르지 않고 `PAGE` 를 거친다.
그래서 화면을 하나 더 붙이는 데 core 를 고칠 일이 없다 (`character` 브랜치가 그렇게 붙어 있다).

## 문서 열람은 꺼 뒀다

인앱에서 문서를 읽지 않기로 했다. 사이드바·문서 페이지 코드는 지우지 않고
`_docs.parked.*` 로 옮겨 뒀고, 셸에서 부르지 않을 뿐이다.

되살리려면 두 파일을 셸에 다시 걸고 `drawSide()` 를 부르면 된다.
`core.js` 가 이미 `S.files` 와 `S.md` 를 다 채워 두므로 그것 말고 필요한 건 없다.

## 목록에 보이는 이름

파일명은 정렬 때문에 번호와 원래 글 제목을 그대로 달고 있다. 목록에서는 그게 다 군더더기다.

- **하위 폴더까지 그룹으로 올린다**: `00_가이드 / 이미지` 가 제목이 되고 파일 줄에는 이름만 남는다.
  파일 줄에 `이미지/` 를 붙이면 `퀄리티/부정프롬` 의 `/` 가 경로처럼 읽혀 헷갈린다
- **번호와 밑줄을 뗀다**: `03_하네스_8블록_템플릿` → `하네스 8블록 템플릿`
- **원문 글은 이름을 따로 정한다**: 제목이 길고 파일명이 곧 글 제목이라 자동 규칙으로는 안 줄어든다

## 읽기 목록에 안 나오는 것

**읽기 탭은 읽을거리만 놓는다.** 두 가지를 뺐다.

| 뺀 것 | 왜 | 어디서 보나 |
|---|---|---|
| `99_작업중/` | 초안은 읽을 문서가 아니라 **내가 방금 만든 것**이다 | 만든 파츠 화면 아래 |
| `01_자료/` | 사전 탭이 훨씬 잘 보여준다 | 에셋 → **사전** |
| `README.md` · `CLAUDE.md` · `문서구분표.md` | 저장소를 굴리기 위한 정비용 문서 | 사이드바 맨 아래 **숨긴 문서도 보기** |
| `02_템플릿/이미지/01·02·03` | **구조가 통째로 화면에 들어갔다**: 더 읽을 게 없다 | 위와 같음 |

흡수된 템플릿은 `ABSORBED` 목록으로 관리한다. 화면이 그 구조를 실제로 갖고 있을 때만 넣는다.
`02_템플릿/챗봇/` 은 캐릭터 화면이 아직 하네스 8블록밖에 안 다루므로 그대로 둔다 (`character` 브랜치).

초안이 읽기 목록에 섞이면 `00_가이드` 옆에 `99_작업중` 폴더가 나란히 서서
"읽을 것"과 "만든 것"이 한 목록에 뒤엉킨다. 그래서 초안은 **만들어진 곳 옆에** 둔다.
이미지 조립으로 만든 것은 이미지 그룹에, 챗봇 작성으로 만든 것은 챗봇 그룹에.

## 화면에 확장자를 쓰지 않는다

`.md` · `.csv` 는 **어디에도 표시하지 않는다.** 파일 목록·문서 상단 경로·초안 이름·알림 문구 전부
`pretty()` 를 거친다. 무슨 파일인지는 **어느 폴더에 있는지와 점 색**이 알려주므로 확장자는 군더더기다.

예외는 둘 뿐이고, 둘 다 사람이 읽는 자리가 아니다.

| 곳 | 왜 그대로 두나 |
|---|---|
| 파일 줄에 마우스를 올렸을 때 뜨는 툴팁 | 진짜 위치를 확인하는 자리다 |
| 정적 모드의 내려받기 파일명 | 실제로 만들어지는 파일이다 |

## 에셋: 사전 · 태그조합 · 최종

찾는 자리와 짜는 자리와 합치는 자리를 나눈다.

```
사전 ─── 일반          찾는 자리. 4,205행을 목적 → 분류 → 세부로 좁힌다
     ├── 작가          140개를 남캐·여캐 견본 그림과 함께
     └── 스타일        88개를 뜻 설명과 함께

태그조합 ─ 그림체       짜는 자리. 각 화면 아래에 그 파츠로 저장한 것이 붙는다
      ├── 외형
      ├── 의상
      └── 장면

최종                   파츠를 골라 26슬롯 순서로 섞는다
```

**저장한 것은 만든 자리 아래에 둔다.** 따로 「작업중」 탭을 두면 만든 곳과 여는 곳이 갈려서,
외형을 고치려고 작업중에 들어갔다가 다시 외형으로 나오는 왕복이 생긴다.

사전에는 **조립 기능이 없다.** 반대로 태그조합의 각 화면에는 **그 파츠 몫의 사전이 접혀 있다**:
찾는 김에 짜는 게 아니라, 짜다가 찾는 흐름이다.

## 생성기: Gem 링크와 지시문을 한 화면에

Gem 에 넣을 지시문과 Gem 링크가 각각 다른 파일에 흩어져 있었다.
정작 쓸 때는 **링크를 열고 지시문을 복사한다** 는 한 동작인데 두 군데를 오가야 했다.

**생성기** 탭이 그 화면 갈래의 것만 모아 보여준다. 여기서는 이미지 쪽만 나온다.

| 갈래 | Gem | 지시문 |
|---|---|---|
| **에셋** | Nai 프롬프트 생성 | Gem 활용: 캐릭터 외형 생성 · Gem 없이: 프롬프트 생성 |
| 캐릭터 (`character` 브랜치) | 캐릭터·세계관 정리 | 하네스 재배치 · 토큰 최적화 · 문체지침 추출 |

- Gem 은 `0-참고링크.csv` 의 `분류 = 생성 도구` 행에서 가져온다
- 지시문의 **정본은 `04_생성기/`** 다. 뷰어는 읽어서 펼칠 뿐 따로 갖고 있지 않는다
- 코드블록마다 `⧉` 가 붙는다. 그 블록이 곧 붙여넣을 지시문이다
- 어느 갈래인지는 파일명에 `이미지` 가 있는지로 가른다

## 사전: 작가는 눈으로 고른다

작가 태그 140개를 글자만 보고 고를 수는 없다. **태그마다 남캐·여캐 견본 그림**을 붙인다.

| 태그 | 남캐 | 여캐 | 비고 | 섹션 |
|---|---|---|---|---|
| `artist: ishikawa hideki` | 🖼 | 🖼 | 네거티브 추천 | 작가태그 |

견본은 `01_자료/이미지/작가샘플/` 에 산다. 파일 이름이 곧 연결고리다.

```
<태그슬러그>_남.webp      ← artist: ishikawa hideki → ishikawa-hideki_남.webp
<태그슬러그>_여.webp
```

슬러그 = `artist:` 를 떼고 소문자로, 영문·숫자·한글이 아닌 것은 `-` 로.
`_남`/`_여` 대신 `_m`/`_f`, `_male`/`_female` 도 받는다. **140개 슬러그가 전부 고유함을 확인했다.**

**빈 칸에 그림을 끌어다 놓으면** 이름을 붙여 저장한다 (`POST /_asset`).
빈 칸에는 기대하는 파일명을 적어두므로 직접 넣어도 된다.
그림 파일(webp·png·jpg·gif·avif)만, 10MB 까지, 그 폴더 밖으로는 못 나간다.

> **webp 를 권한다.** 280장이 쌓일 자리다. 원본 PNG 를 그대로 넣으면 저장소가 금방 무거워진다.

견본 목록은 로컬에서는 폴더를 훑어 찾고, 정적 호스팅에서는 `manifest.json` 의 `samples` 를 쓴다
(그림은 확장자가 달라 문서 목록에 안 잡힌다). 그림을 추가했으면 `node viewer/build-manifest.mjs`.

## 에셋: 프롬프트는 한 덩어리로 짜지 않는다

성격이 다른 네 묶음을 **따로 만들어 두고 조립한다.** 각각 갈아끼우는 주기가 다르다.

| 파츠 | 무엇 | 얼마나 자주 바뀌나 |
|---|---|---|
| **그림체** | 작가태그 6단 + 모델·Steps·Guidance·Seed + 퀄리티/부정 | 한 번 깎으면 계속 쓴다 |
| **외형** | 그 캐릭터를 그 캐릭터이게 하는 것 | 캐릭터당 하나 |
| **의상** | 옷 + 장신구 | 같은 캐릭터라도 자주 |
| **장면** | 구도 · 상황 · 행동 · 마무리 | 캐릭터를 안 가리고 재사용 |

### 태그 사전도 파츠마다 갈린다

의상을 짜는 중에 작가 태그가 보일 이유가 없다. **각 파츠 화면 안에 그 파츠 몫의 사전이 붙어 있다**:
짜던 자리를 떠나지 않고 찾아서 바로 넣는다.

| 파츠 | 사전에 들어오는 목적 | 행 |
|---|---|---:|
| **그림체** | 작가 · 스타일 | 228 |
| **외형** | 캐릭터 · 외형 | 747 |
| **의상** | 의상 | 658 |
| **장면** | 장면·구도 · 동작·표정 · 성인 · **등장·원작** | 2,800 |

누른 태그는 담기지 않고 **그 태그가 속한 슬롯 칸에 바로 들어간다.**
그림체에서는 `artist:` 로 시작하면 ③작가, 아니면 ②화풍으로 간다.
전 태그 4,508개가 자기 파츠 슬롯으로 떨어지는 것을 확인했다. 거부되는 태그는 없다.

**NSFW 숨김 토글은 그 파츠에 NSFW 태그가 실제로 있을 때만 나온다.**
파일을 훑어 판단하므로 CSV 가 바뀌면 따라간다.

| 파츠 | NSFW | 토글 |
|---|---:|---|
| 그림체 | 0 | 없음 |
| 외형 | 0 | 없음 |
| 의상 | 20 | 있음 |
| 장면 | 447 | 있음 |

전 태그 4,508개가 자기 파츠 슬롯으로 떨어진다. 거부되는 태그는 없다.

숨겨서 목록이 비면 **몇 건이 가려졌는지 같이 적는다**: 「성인」 갈래를 고르면 430건이
전부 NSFW 라 빈 목록이 나오는데, 이유가 안 보이면 고장으로 읽힌다.

> **슬롯은 태그 글자가 아니라 누른 행으로 정한다.**
> 같은 글자가 여러 시트에 있다 (`face` 는 외형에도 장면에도, `miko` 는 의상에도 직업에도).
> 글자로 다시 찾으면 첫 행을 집어 엉뚱한 슬롯으로 간다.
> **사전** 탭이 전체를 훑는 자리다. 거기서 담은 것은 각 파츠의 «담은 태그 넣기» 로 넘어온다.

### 26슬롯을 셋이 갈라 가진다

| 파츠 | 슬롯 |
|---|---|
| **외형** | 01 성별 · 04 얼굴 · 05 머리 · 06 상체 · 07 하체 · 09 직업·종족 |
| **의상** | 14 장르 · 15 재질 · 16 구조 · 17 상의 · 18 겉옷·팔 · 19 하의·다리 · 20~23 장신구·신발 |

꼬리·날개는 **몸의 일부**라 06 상체 · 07 하체로 보낸다. 26슬롯의 22번은 장식으로 다는 날개 자리다.

**02 캐릭터는 외형이 아니라 장면이다.** 원작 캐릭터 이름(`mash kyrielight`)이나
관계(`father_and_daughter`)는 **내 캐릭터의 고정 외형이 아니라 이 그림에서만 쓰는 것**이고,
같은 캐릭터를 두고 그림마다 갈아끼운다. 외형 파츠는
`02_템플릿/이미지/03_캐릭터_외형고정_템플릿.md` 가 말하는 «매번 같은 얼굴을 뽑기 위한 고정 블록» 이다.

> 시트 이름만으로는 안 갈리는 게 하나 있다. `태그인물 / 인물` 37행은 전부
> `father_and_daughter` · `aunt_and_nephew` 같은 **관계** 태그다. 그 캐릭터의 외형이 아니라
> '이 그림에 누가 같이 나오는가' 라서 원작 캐릭터와 같은 자리(02)로 보낸다.
> `P_OVERRIDE` 에 `시트|분류1` 로 예외를 적어둔다.
| **장면** | 00 카메라·구도 · **02 캐릭터** · 03 시선 · 08 신체 상태 · 10 상황 · 11 자세 · 12 동작 · 13 감정 · 24 배경 · 25 소품 · 26 분위기 |

> **조립은 묶음을 이어 붙이는 게 아니라 슬롯 번호로 다시 섞는 것이다.**
> 장면의 `00 카메라` `03 시선` 은 외형의 `04 얼굴` 보다 **앞에** 와야 한다.
> 이어 붙이면 순서가 깨진다. 그래서 파츠 파일에는 태그만이 아니라 **슬롯 번호를 살려 적는다**:
> 한 줄로 뭉쳐 두면 어느 슬롯 것인지 잃어버려 다시 섞을 수 없다.

### 조립 결과는 칸이 나뉜다

### 그림체: 작가태그 6단

> **아무 차이 없는 선택지**가 됐다. 차이가 생길 때만 버튼이 나오게 바꿨다.

## 태그 탭: 목적으로 고른다

**세 CSV 를 한 표로 합쳤다.** 태그사전 4,205 + 스타일태그 88 + 작가태그 140 = **4,433행.**
파일이 셋으로 나뉜 건 출처가 다르기 때문이지, 쓰는 자리가 다른 게 아니다.
프롬프트를 짤 때는 "지금 옷을 고르는 중" 이지 "지금 태그사전을 보는 중" 이 아니다.

그래서 맨 위 갈래를 **목적**으로 잡는다. 시트 이름은 내용과 어긋나기도 한다.
`태그동작2` 안은 전부 `dress_pull` `mask_lift` 같은 **옷을 다루는 동작**이다.

## 참고링크는 태그가 아니다

`0-참고링크.csv` 는 **아직 저장소로 못 옮긴 바깥 자료** 목록이다.
태그를 고르는 드롭다운에 섞여 있을 이유가 없어서 뺐다.
문서 목록에서 누르면 **문서 그룹에 머문 채** 본문 자리에 표로 편다.

참고링크 파일은 **에셋과 캐릭터가 따로 있고, 누른 쪽 것만 보여준다.**
둘을 합쳐 놓으면 에셋 링크 아래에 캐릭터 쪽 Gem(`캐릭터·세계관 정리`)이 딸려 나온다.

이미 옮긴 것은 지운다. `로컬 파일` 칸이 어디로 갔는지 알려주므로 그게 채워지면 목록에서 뺀다
(`일부 반영` 은 아직 남은 게 있다는 뜻이라 유지). 이 규칙으로 18건 → 13건이 됐다.

## CSV 를 누르면 그 자료가 있는 자리로 간다

| 누른 것 | 가는 곳 |
|---|---|
| `태그사전` | 에셋 → 태그 (목적 전체) |
| `스타일태그` | 에셋 → 태그, **목적 = 스타일** |
| `작가태그` | 에셋 → 태그, **목적 = 작가** |
| `참고링크` | 문서 그룹에 머문 채 링크 표 |

예전에는 무엇을 누르든 에셋 탭 첫 화면으로 떨어져서, 스타일태그를 눌러도 태그사전이 열렸다.

## 초안: 저장 · 수정 · 삭제

**조립**과 **작성** 탭에 이름 칸과 `작업중에 저장` 버튼이 있다.

```
이미지 → 조립 → 저장   →  99_작업중/이미지/<이름>.md
챗봇   → 작성 → 저장   →  99_작업중/챗봇/<이름>.md
```

같은 이름이 있으면 덮어쓸지 묻는다. 입력한 이름은 기억한다.
저장되는 파일에는 `03_프롬프트/README.md` 의 **파일 머리말**(플랫폼·언어·형식·글자수·최종 수정)이
자동으로 붙는다. 승격할 때 그대로 쓰면 된다.

**작업중** 탭에서 초안 하나를 누르면 그 자리에서 펼쳐진다.

| 버튼 | 하는 일 |
|---|---|
| **수정** | 본문을 textarea 로 펼친다. 고치고 **저장** → `POST /_edit` |
| **복사** | 본문 전체를 클립보드로 |
| **삭제** | 확인 후 파일을 지운다 → `POST /_delete`. 되돌릴 수 없다 |

정적 호스팅에서는 **보기·복사만** 되고 수정·삭제 버튼은 나오지 않는다 (쓰기 엔드포인트가 없다).

## 파일 목록을 찾는 방법

1. `viewer/manifest.json` 이 있으면 그걸 쓴다. **정적 호스팅(GitHub Pages)용**
2. 없으면 서버의 디렉터리 목록을 훑는다. 로컬 서버용

목록은 부팅 때 한 번 읽는다.
- **저장·삭제하면** 목록에 바로 반영된다
- **터미널에서 파일을 만들었다면** 상단 `새로고침`
- **manifest 를 쓰는 중이라면** 파일을 추가한 뒤 다시 만들어 커밋해야 반영된다

```bash
node viewer/build-manifest.mjs
```

## GitHub Pages 로 링크 만들기

저장소가 **공개**여야 무료 Pages 를 쓸 수 있다.

```bash
node viewer/build-manifest.mjs && git add -A && git commit -m "manifest" && git push
```

저장소 → Settings → Pages → Source `Deploy from a branch` → `main` / `/ (root)`

정적 호스팅에서는 **저장·수정·삭제가 자동으로 숨겨진다.**
읽기·검색·조립·검토는 전부 동작한다.

## 마크다운 렌더러: 원문 글의 표기까지 받아낸다

`00_가이드/` 의 `[원문]` 문서는 포스타입에서 그대로 옮겨 온 것이라
보통 마크다운에는 없는 모양이 섞여 있다. 정규식 하나로는 못 잡아 **글자로 새어 나왔다.**
지금은 대괄호·괄호 짝을 직접 세며 훑는다.

| 원문 표기 | 예 | 결과 |
|---|---|---|
| 5·6단계 제목 | `##### 01. 작가 태그 조합` | 소제목 (포스타입이 제일 많이 쓴다. 71회) |
| 취소선 | `~~지나간 계획~~` | 취소선 |
| 백슬래시로 막은 기호 | `\# 출력 방식` | `# 출력 방식` (제목으로 보지 않는다) |
| 대체 텍스트가 빈 이미지 | `![](https://…png)` | 그림 (누르면 원본) |
| 링크 글자 안에 대괄호가 또 | `[[Nai] 그림 그리는 법](url)` | 링크 |
| 링크 글자가 빈 것 | `[](url)` | 주소를 글자로 쓴 링크 |
| 여러 줄 링크: 안이 **글** | <code>[</code> ⏎ `##### 제목` ⏎ <code>](url)</code> | **링크 카드** (제목 · 부연 · 도메인) |
| 여러 줄 링크: 안이 **그림** | <code>[</code> ⏎ `![](img)` ⏎ <code>](img)</code> | 그냥 그림 |
| 닫는 줄에 다음 블록이 붙음 | `](urlA)[` | 둘 다 따로 처리 |
| 맨 주소 | `https://…` 만 적힘 | 자동 링크 |

`http` `mailto` `#` 상대경로만 링크로 만든다. `javascript:` 는 글자로 흘린다.
코드(`` ` ``) 안의 대괄호는 링크로 보지 않는다.

> 저장소의 md 45개를 전부 렌더해 **마크다운 표기가 글자로 새어 나오는 곳이 0** 임을 확인했다.
> 제목은 `#{1,4}` 까지만 받다가 `#####` 56곳이 글자로 노출됐던 것을 고쳤다.
> 원문 파일의 본문은 한 글자도 고치지 않았다. `[원문]` 은 편집 금지이므로 렌더러 쪽에서 받아낸다.

## 그림: 남의 CDN 이 막아서 저장소에 보존한다

`00_가이드/` 원문 글의 스크린샷은 **포스타입 CDN(CloudFront)에 있고, 그쪽이 핫링크를 막는다.**

| 요청의 Referer | 응답 |
|---|---|
| 없음 | `403` |
| `http://localhost:8799/` | `403` |
| `https://www.postype.com/` | `200` |

브라우저는 `<img>` 에 **가짜 Referer 를 실을 수 없다.** 페이지에서 주소를 그대로 걸면 무조건 403이다.

### 보존해 둔 사본을 쓴다

```bash
node viewer/archive-images.mjs          # 313장 → viewer/img/ · 21MB
node viewer/archive-images.mjs 1000 90  # 화질을 직접 지정하고 싶을 때
```

- `viewer/img/<해시>.webp`: 그림 파일
- `viewer/images.json`: 원본 주소 → 파일명. 뷰어가 이걸 보고 `src` 를 갈아끼운다

**둘 다 커밋한다.** 그래야 원본이 지워져도, 다른 컴퓨터에서 clone 해도, GitHub Pages 에서도 보인다.
이미 받은 건 건너뛰므로 문서에 그림을 새로 넣은 뒤 다시 돌리면 된다.

> **왜 webp 이고 왜 21MB 인가.** 원문 그림은 대부분 스크린샷 **PNG** 라 `q=` 가 안 먹는다(무손실).
> `w=1000` → `w=800` 만으로는 106MB → 103MB, 사실상 그대로였다.
> 그런데 이 CDN 은 **`Accept` 헤더로 형식을 협상한다**: `image/webp` 를 받겠다고 하면
> 같은 그림을 webp 로 준다. 한 장 기준 **172KB → 34KB**. 그래서 313장이 21MB 로 들어간다.

### 아직 보존 안 한 그림은 서버가 대신 받아 온다

```
<img src="/_img?u=<원본 주소>">
      → serve.mjs 가 Referer 와 Accept 를 붙여 받아옴
      → viewer/.imgcache/ 에 저장 (커밋하지 않는 임시 캐시)
```

그림 주소를 만나면 **① 보존 사본 → ② `/_img` 통로 → ③ 원본 주소** 순으로 내려간다.
셋 다 실패하면 깨진 아이콘 대신 **"그림을 불러오지 못했습니다. 원본 열기"** 자리로 바뀐다.

`REFERER` 표에 호스트별로 보낼 Referer 를 적어둔다. 없는 호스트는 그 주소의 origin 을 쓰고,
그래도 막히면 Referer 없이 한 번 더 시도한다.
받아 온 형식이 주소의 확장자와 다를 수 있으므로(`.png` 주소에 webp 가 온다)
캐시 파일은 **실제로 받은 형식**으로 이름 붙인다.

`/_img` 는 그림을 받아오는 통로지 범용 프록시가 아니다. 사설망 주소(`127.` `10.` `192.168.` …)와
`image/*` 가 아닌 응답, 20MB 초과는 거부한다.

## 디자인 · 반응형

색·간격·컨트롤을 **AIchatCollector 와 같은 체계**로 맞췄다. 두 도구를 오갈 때 손이 헷갈리지 않게.

**① 창 폭 (미디어 쿼리)**

| | 하는 일 |

> 사이드바를 넓히면 창은 그대로여도 헤더가 좁아지므로 미디어 쿼리로는 못 잡는다.

> 서브탭(태그·조립·검토·작업중)은 주 내비게이션이라 **기본으로 펼쳐 둔다.**

## 입력 중 기호 변환

저장소 표기 규칙(`→` `·`)에 맞춰 챗봇 작성 탭에서 타이핑하는 즉시 바꾼다.

| 입력 | 결과 | | 입력 | 결과 |
|---|---|---|---|---|
| `->` | `→` | | `...` | `…` |
| `<-` | `←` | | `!=` | `≠` |
| `=>` | `⇒` | | `>=` `<=` | `≥` `≤` |

`조건 -> 반응` 을 그대로 치면 `조건 → 반응` 이 된다. 검토 탭의 Trigger 개수도 `→` 로 세므로
바꿔 두는 편이 유리하다. 백스페이스로 지울 때는 변환하지 않는다.

## 글자수 세기 (챗봇 작성 탭)

입력하는 즉시 집계한다.

- **블록마다** 라벨 오른쪽에 글자수: 어느 블록을 줄일지 바로 보인다
- **상단 요약**: 글자수 · 공백 제외 · 한글 · 토큰 추정
- **제한** 칸에 숫자를 넣으면 게이지와 남은 글자수가 뜬다.
  85%를 넘으면 주황, 초과하면 빨강으로 바뀌고 초과분을 표시한다. 입력한 제한값은 저장된다

> 플랫폼별 제한 수치는 저장소에 자료가 없어 직접 넣는다.
> 토큰 추정은 한글 1.4 · 그 외 0.3 으로 잡은 **어림값**이다. 실제 토크나이저와 다르다.
> 토큰제 플랫폼이면 `04_생성기/02` 로 영문 변환을 검토한다.

## 이미지 검토가 판정하는 것

| 항목 | 방식 |
|---|---|
| A1 태그 실재 | 태그사전 + 스타일태그 + 작가태그 대조 |
| A2 언더바 | `_` 포함 여부 |
| A3 NSFW | 사전의 `NSFW=TRUE` 467행과 대조 |
| B2 숫자 끝 | 닫는 `::` 앞이 숫자인데 공백이 없는 경우 |
| B4 `::` 짝 | 개수가 홀수인지 |

**A1 은 두 갈래로 나눠 보고한다.** 태그사전엔 없지만 Q·N 프리셋에서 쓰는 어휘
(`8k` · `dramatic contrast` 등 177개)는 정상으로 처리한다. 태그사전이 2022년 danbooru 기준이라
퀄리티·조명 어휘가 아예 없기 때문이다. 어디에도 없는 것만 "확인 필요"로 올린다.

가중치 그룹 안의 쉼표(`3::a, b, c::`)는 최상위 구분자로 세지 않고, 그룹 안 개별 태그도 각각 검사한다.

## 챗봇 검토가 판정하는 것

| 항목 | 방식 |
|---|---|
| A1 형식 통일 | XML · Markdown · YAML · INI · 블록(`[ ]`) 중 몇 가지가 섞였는지 |
| A2 언어 통일 | 줄마다 주도 문자를 세어 한/영/중 비율 산출 |
